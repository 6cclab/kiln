# Broader partial Go verification discovery

`verificationDiscover: "go"` now accepts literal `go test ./path`, `go test ./path/...`, and module-root `go test ./...`. It snapshots the selected tree, root Go metadata, transitively imported packages whose import paths belong to the root module, and local replacement directories named in `go.mod`. Imports are read statically with `go/parser` in `ImportsOnly` mode. No additional command runs, and the wrapper still executes the requested Bash command when discovery fails or exceeds a limit.

Evidence remains `go-partial-v1`. Status compares the recorded files and directories and can suggest rerunning the recorded command when one changes. Unchanged inputs do not establish test correctness and never justify skipping verification. The existing shared file, directory, entry, and byte limits apply to all discovered and declared inputs; exceeding any limit saves no partial proof. Discovery reads at most the remaining entries plus one from each directory before rejecting a large tree, and refuses Go source files above 1 MiB.

Unsupported command forms are shell expansion or quoting, flags, compound commands, assignments, and redirects. Build tags and cgo no longer disable discovery; see "Closing the known gaps" below. Imports of modules outside the root and any workspace are not traced, except that local `go.mod` replacement targets are snapshotted even when a relative or absolute target lies outside the module root. These external paths require Read permission, retain their canonical relative or absolute spelling, and share the existing limits. The tool result records the unsupported discovery reason in `taskVerificationAttempt.discoveryUnsupported` and the status scope states the remaining limits of partial evidence.

## T2 Windows cross-volume ancestor traversal

When a module and an absolute local replacement are on different Windows volumes, `filepath.Rel` cannot relate them. `verificationCommonAncestor` ascends the module path and returns its volume root (`C:\` for `C:\module`), while `filepath.Dir` of the replacement's drive or UNC root returns that same target root. Both the file and directory fingerprint loops previously looped forever. The shared ancestor walker now returns `verification ancestor unavailable across volumes` at a fixed point. Discovery records that reason in `taskVerificationAttempt.discoveryUnsupported`, saves no partial proof, and still runs the requested Bash command. Existing permission and symlink checks remain in the walker; evidence limits and the `go-partial-v1` scope are unchanged.

`TestVerificationCrossVolumeAncestorTraversal` uses Windows-shaped drive and UNC parent maps to exercise both traversal forms on a non-Windows host. Removing only the new fixed-point guard made both subtests fail in under a second with `context canceled`; restoring it made them pass. `TestVerificationSameVolumeAncestorTraversal` checks the ordinary stopping point. `TestGoVerificationExternalReplaceUnavailableStillRuns` checks denied Read permission and a symlinked replacement: each yields an explicit unavailable reason and no proof, while the requested command runs once. The existing `TestGoVerificationDiscoverySiblingAndAbsoluteReplace` also passed.

`TestVerificationWindowsCrossVolumePathSemantics` checks actual Windows `filepath.Rel` and drive/UNC root behavior, and the Windows test binary cross compiled with `GOOS=windows GOARCH=amd64 GOCACHE=/tmp/kiln-go-cache go test ./internal/tools -c -o /tmp/kiln-tools-windows.test.exe`. This Mac host has no available native Windows runner, so the Windows-only test was not executed. The first sandboxed `make check` could not resolve the pinned staticcheck download; the approved network retry of `GOCACHE=/tmp/kiln-go-cache make check` passed, including gofmt, vet, staticcheck, unit tests, and e2e package vet. Native Windows execution remains the validation gap; unchanged evidence still makes no safe-to-skip claim.

### Review correction

The Windows-only test originally expected `verificationCommonAncestor` to return `C:\module`. The Go 1.27.3 source at `src/path/filepath/path.go` (`Rel`) rejects different volume names; `src/internal/filepathlite/path.go` (`Dir`) ascends `C:\module` to `C:\` and holds a volume root fixed. The test now expects `C:\`, then checks that the ancestor walker returns unavailable evidence for both a `D:\` file and a UNC directory. This is source-level verification and Windows cross-compilation, not native Windows execution.

The Read-denial test now derives `..` plus `external` with `filepath.Join`, matching the replacement path canonicalized by `parseGoDiscoveryMod` on both slash conventions. It also requires the denial callback to have seen that canonical path, so an accidentally permissive predicate cannot make the test pass for an unrelated reason. Temporarily changing the denied target to `../wrong` made `TestGoVerificationExternalReplaceUnavailableStillRuns/read_denied` fail immediately with “Read permission was not checked”; restoring the target made the focused suite pass. The corrected focused tests passed on macOS, and `GOOS=windows GOARCH=amd64 GOCACHE=/tmp/kiln-go-cache go test ./internal/tools -c -o /tmp/kiln-tools-windows-review.test.exe` cross compiled. The old Windows-only assertion cannot be run red on this Mac; the old read predicate only differs on Windows, so its platform-specific failure is source-level evidence rather than a claimed executable failure. Native Windows execution, including the full cross-volume wrapper path and Windows Read/symlink behavior, remains open.

After these review corrections, `GOCACHE=/tmp/kiln-go-cache make check` passed with gofmt, vet, staticcheck, the full unit suite and e2e package vet.

## Closing the known gaps (go-partial-v2)

- **Workspace modules.** When `go.work` exists, each `use` directory inside the root has its `go.mod` read and its module path joins the import map (longest module-path prefix wins), so imports into it are traced like in-module packages. Each used module root is snapshotted whole (packages traced inside it are not listed again); a root already inside the selected tree is skipped. A used module outside the root is snapshotted whole but its imports are not traced (its module path is not read). `go.work` and used-module `replace` targets that are local are snapshotted like root `replace` targets. A go.work or used-module `go.mod` that cannot be read or parsed saves no proof.
- **Build tags and cgo.** Every `.go` file in a scanned directory is parsed for imports regardless of `//go:build` or `// +build` lines, test files included; `import "C"` is ignored. Because directory snapshots include every file, cgo sources and headers (`.c .h .s .S .cc .cpp .m .syso` and the rest) and `//go:embed` targets (always inside the package directory tree) are covered without being parsed. The result is a superset, which can only suggest a rerun.
- **External modules.** `go.mod`, `go.sum` and `go.work.sum` are recorded as before, so any dependency version change flips status. The module cache is not read.
- **Toolchain and environment.** The `go` and `toolchain` lines are part of the hashed `go.mod`/`go.work`. The evidence adds `env`: the values of `CGO_ENABLED`, `GOARCH`, `GOEXPERIMENT`, `GOFLAGS`, `GOOS`, `GOTOOLCHAIN` and `GOWORK` that are set in kiln's process environment at recording time (unset variables are recorded as absent; a value over 4096 bytes saves no proof). Status and freshness compare them with the current environment and report changed names in `env`. No command runs.
- **Compatibility.** The label is now `go-partial-v2` because the evidence shape gained `env`. `go-partial-v1` records are still accepted (and must not carry `env`); they compare no environment.
- **Kept.** Shared limits (exceeding any saves no partial proof), unsupported command forms with explicit reasons, the requested command always running, and unchanged evidence never justifying a skip.

Tests: `TestGoVerificationDiscoveryBuildTaggedAndCgoFilesFlipStatus`, `TestGoVerificationDiscoveryEmbedTargetFlipsStatus`, `TestGoVerificationDiscoveryWorkspaceModules`, `TestGoVerificationDiscoveryWorkspaceModuleOutsideRoot`, `TestGoVerificationDiscoveryWorkspaceLimitSavesNoProof`, `TestGoVerificationDiscoveryGoSumAndToolchainFlipStatus`, `TestGoVerificationDiscoveryEnvironmentFlipsStatus`, `TestGoVerificationDiscoveryV1RecordsStillReadable`, `TestGoVerificationDiscoveryOversizedEnvironmentSavesNoProof`. Re-enabling the old build-tag rejection, disabling workspace tracing, and disabling the environment comparison each made the matching tests fail; restoring made them pass. The embed test passed before the change too, because recursive directory snapshots already covered embed targets; it pins that behaviour.

Remaining gaps: environment variables not listed, `go env -w` / `GOENV` files, the `go` binary and module cache contents, imports traced from workspace modules outside the root, and ancestor `go.work` files.
