# Independent review: memory import

Review order: 02, 04, 01, 03. Scores are correctness/robustness, security/privacy, design/maintainability, test quality, scope/usability, each 0–4. I reviewed source and submitted tests without changing candidate artifacts. All four pass 29/29 hidden acceptance cases, targeted race and e2e memory tests, build, gofmt, vet, and staticcheck. All four full unit runs fail the same unrelated TUI timeout, also reproduced in the baseline control. I did not treat that as an import defect.

## Candidate 02 — 2 / 2 / 2 / 2 / 2; major revisions

- **Contract violation, reproduced:** `internal/cli/personal_memory.go:217` calls `dec.More()` after decoding the array. That is not a strict EOF check: input `[]]` or `[]}` succeeds and prints success JSON. Fidelity probes reproduce both; the contract requires exactly one JSON array with no trailing data. The submitted malformed-input test includes `[] []`, which happens to be caught, but misses closing delimiters.
- **Contract violation, reproduced:** `internal/memory/store.go:460–495` updates/inserts memories, search rows, and sources during dry run, then relies on rollback. A valid dry run with a database trigger rejecting INSERT fails instead of returning prospective counts. Supplemental probe reproduces the failure. The contract requires conflict analysis without writing records, history, search entries, or bindings.
- **Compatibility regression, reproduced:** `cmd/kiln/main.go:75–80` dispatches every `memory` invocation before the shared parser. `kiln memory --help` now exits 2 with usage rather than showing help. The supplemental probe confirms it. Import-only dispatch would preserve existing command behavior.
- **Contract violation, reproduced:** `internal/memory/sources.go:101` rebinds through `sourceDigest`, which opens the destination (`sources.go:30`) before checking its file type. A FIFO at the rebound path blocks rather than being rejected as nonregular. Supplemental probe times out after three seconds. This affects source-bearing historical rows too.
- **Privacy concern, inferred:** `internal/memory/store.go:454` includes the imported key in a conflict diagnostic; a key containing credential material would be echoed to stderr. The contract prohibits echoing credentials. The CLI tests check text secrecy but not sensitive keys.

The selected-key collapse, global rejection of historical invalid rows, scope assignment, and transaction rollback on ordinary errors are sound. Validation happens before `Store.Import`; the transaction handles conflicts and writes. Source rebind checks lexical containment, SHA-256, destination hash, symlink escape, and size through `sourceDigest`, subject to the FIFO flaw. Tests cover round trip, basic flags, malformed input, policies, dry-run final state, and source paths, but omit strict trailing delimiters, dry-run write attempts, and a nonregular source. Documentation describes the command and policies accurately aside from those defects. The broad raw dispatch is unnecessary scope change.

## Candidate 04 — 3 / 2 / 4 / 3 / 4; minor revisions

- **Contract violation, reproduced:** `internal/memory/import.go:139` calls `sourceDigest`, which opens a rebound FIFO before the regular-file check at `internal/memory/sources.go:30–39`. The import hangs rather than rejecting a nonregular source; the supplemental probe times out. A source-bearing historical record can trigger it.

The importer validates every row, selects the largest ID per key, rejects global sources/nonpreferences, and uses a single transaction. `internal/memory/import.go:256–258` skips writes during dry run, and `:265–284` writes lineage, search, and bindings only for selected keys. The narrow dispatch in `cmd/kiln/main.go:81–90` preserves other memory commands. Parsing checks EOF after the array (`internal/memory/import.go:55–59`), including stray closing delimiters in fidelity probes. Source logic checks lexical containment, SHA-256, destination contents, and symlink boundaries, subject to the shared FIFO flaw. Submitted tests are broad and behavioral for parsing, history, scope, conflicts, expiry, source rebinding, and dry-run final state. `TestImportAtomicOnFailure` (`internal/memory/import_test.go:358–376`) proves prevalidation only, not rollback after a database write failure; hidden acceptance covers write failures. Documentation is clear and no dependency or unrelated refactor appears.

## Candidate 01 — 3 / 2 / 4 / 3 / 4; minor revisions

- **Contract violation, reproduced:** `internal/memory/import.go:276` calls `sourceDigest`, which opens a rebound FIFO before checking regular-file status (`internal/memory/sources.go:30–39`). The supplemental probe times out rather than receiving a rejection. The all-history validation means even a historical FIFO binding can hang.

`internal/memory/import.go:71–124` validates every row and rebinds sources before database mutation, then selects highest IDs and analyzes conflicts. `:158–194` avoids all inserts for a dry run and applies real batches in one transaction. Destination scope, creation time, IDs, expiry, and supersedes handling follow the contract. The import-only dispatch (`cmd/kiln/main.go:78–85`) preserves existing memory help; strict trailing JSON handling (`internal/cli/memory_import.go:172–178`) passes fidelity probes. Source lexical containment, digest checks, and symlink containment are sound apart from the FIFO behavior. Submitted tests exercise history collapse, policy behavior, dry-run final state, global restrictions, source changes and escapes, and bounds. They do not test nonregular source blocking or a write-trigger rollback; hidden acceptance covers ordinary database rollback. Documentation is thorough. One optional usability concern: `internal/cli/memory_import.go:65` echoes an unexpected positional argument, which could contain user-provided sensitive text, although it is outside a valid export record.

## Candidate 03 — 2 / 2 / 3 / 2 / 3; major revisions

- **Contract violation, reproduced:** `internal/memory/import.go:101–128` updates and inserts records, search rows, and sources on a dry run, then rolls back. The supplemental INSERT-rejecting trigger makes a valid dry run fail. Dry run must do validation and conflict analysis without these write attempts.
- **Contract violation, reproduced:** `internal/memory/sources.go:118` calls `sourceDigest`, which opens a rebound FIFO before testing regular-file status (`sources.go:30–39`). The supplemental probe times out; the contract requires rejection of nonregular sources.
- **Privacy concern, inferred:** `internal/memory/import.go:91` includes the existing key in the conflict error. A key containing a credential would be emitted on stderr. The contract prohibits echoing credentials.

The CLI validates all history before selection, rebinds only to the current project, and rejects invalid global history (`internal/cli/memory_import.go:209–260`). It strictly rejects trailing data and has import-only dispatch, preserving memory help. Selected rows are written in one transaction, so ordinary write failures roll back. The store API itself accepts preselected records and per-row scopes; CLI prepares them correctly, though the split places important trust assumptions across packages. Tests cover policies, basic bounds, history, and source rebinding, but miss write-attempt dry runs, FIFO sources, and database write rollback. Documentation explains the feature and options. No unrelated change or dependency is evident.

## Comparison and uncertainty

01 and 04 are close: both satisfy the ordinary CLI contract and differ mainly in organization and test emphasis. Both need the same concrete regular-file-before-open source fix. I classify that as minor revisions because the fix is localized to source-file validation, although the reproduced explicit contract violation still blocks merge until fixed and covered by a regression test. 02 has additional strict-JSON and existing-help regressions; 02 and 03 additionally violate dry-run no-write semantics. Every candidate passes the main hidden suite, which did not cover these supplemental edge cases. The FIFO probe uses a real named pipe, so its failure is observable, but a maintainer may decide how to bound or reject unusual input-file types separately; the explicit source-file rule is unambiguous. The shared full-unit TUI timeout is baseline-confirmed and is not evidence against these patches. No candidate should be merged without fixing its explicit contract violations and adding corresponding regression tests.
