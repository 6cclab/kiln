## Candidate 01

**Contract finding, moderate — imported scope improperly governs project validation.** `internal/memory/import.go:67–69` rejects a `fact` or source-bearing record when its *input* scope is `user:preferences`, even when the destination is an ordinary project. The task says imported scope is not destination identity, and reserves the preference-only rule for explicit global import. Reproduction: from a project, import `[ {"id":1,"scope":"user:preferences","key":"k","kind":"fact","text":"value","evidence":"user","created":1} ]`; the command exits 1 with `memory import has invalid global record`, whereas a project import should accept this otherwise valid row. I reproduced this with the built CLI; the independent `project_scope_isolation` and `replace_lineage` checks fail for the same reason. Such a row cannot be produced through ordinary global `Put`, so practical exposure is narrower than an arbitrary exported-format input, but the stated destination rule is still violated. The fix is localized to validating against the requested scope.

**Submitted-test portability, minor — exact spelling of canonical paths.** `internal/memory/import_test.go:149–150` and `internal/cli/memory_import_test.go:86–89` compare `t.TempDir()` paths to stored canonical paths literally. On macOS `/tmp` resolves to `/private/tmp`; unit and targeted race runs fail on those assertions. The same targeted tests pass with a canonical temporary directory. This is a test portability defect, not evidence that source rebinding or project scope is wrong at runtime. The unchanged TUI `TestHandleSubmit_LeadingPathIsNotACommand` also failed in the broad unit run and was reproduced on baseline; it does not belong to this patch.

The implementation bounds file reads to 4 MiB before allocation, rejects unknown/trailing JSON and historical invalid rows, selects highest IDs, and checks all selected conflicts inside one transaction (`internal/cli/memory_import.go:79–86`, `internal/memory/import.go:36–47,49–92,93–164`). It validates destination source files before hashing, including regularity and size, and prevents lexical and symlink escapes (`internal/memory/import.go:167–206`). Import diagnostics do not echo memory text. Its tests cover expiration/stale conflicts, history, global restrictions, source escapes, pre-cancellation, and trigger-injected rollback across memory, search, and source tables. Cancellation during the database wait passes independent evaluation. The documentation explains flags, conflict policies, history collapse, source rebinding, and JSON counts. Build, formatting, vet, staticcheck, memory e2e, 27 of 29 hidden acceptance cases, and all supplemental/fidelity probes pass.

## Candidate 02

**Contract and availability blocker, high — FIFO source blocks import.** `internal/memory/import.go:202–204` calls `sourceDigest` without checking destination file type. In `internal/memory/sources.go:30–39`, `os.Open(resolved)` happens before `f.Stat()` and the regular-file check. Reproduction: create a FIFO at the destination root-relative source path (`mkfifo project/pipe`), supply a well-formed 64-digit source hash and an original absolute root, then run `kiln memory import input.json`. With no writer on the FIFO, the command blocks before it can reject the nonregular source; cancellation cannot interrupt the blocking open. The independent FIFO probe terminated it after three seconds. The task explicitly requires rejecting nonregular source files. This is a focused fix, but a blocker for a safe importer because untrusted input can hang the management command.

**Submitted-test portability, minor — exact spelling of canonical paths.** `internal/memory/import_test.go:196–198` expects `t.TempDir()` spelling to equal the stored canonical root and path. The original unit and targeted race runs fail under `/tmp` → `/private/tmp`; both targeted runs pass with canonical TMPDIR. This does not establish a runtime rebinding fault. The broad unit run also includes the baseline-reproduced, unchanged TUI timeout.

The core import validates a destination-scoped copy, historical rows and IDs, and source boundaries (`internal/memory/import.go:37–97,181–207`). Conflict analysis and all writes use one transaction, with contextual SQL calls and rollback on errors or cancellation (`internal/memory/import.go:104–178`). CLI parsing accepts import flags after the filename and rejects unknown flags, missing values, extra operands, and invalid policies (`internal/cli/args.go:194–199`, `internal/cli/personal_memory.go:149–203`). Tests cover history, scope isolation, conflict modes, validation, source escapes, cancellation before import, and trigger-injected rollback. They test directories and oversized files, but not blocking nonregular files. Documentation accurately describes the intended behavior. Build, formatting, vet, staticcheck, memory e2e, all 29 hidden acceptance cases, and all supplemental/fidelity probes other than FIFO pass.

## Comparison and uncertainty

Candidate 02 handles imported scope as the task specifies and therefore passes two acceptance cases candidate 01 fails. Candidate 01 prechecks nonregular source files and returns promptly on a FIFO, while candidate 02 can hang indefinitely. I favor candidate 01 as the safer starting point because its observed defect is a localized rejection of unusual input; candidate 02's observed defect is an availability failure on an expressly rejected source type. Neither is ready unchanged. A maintainer should confirm whether “existing Put field/kind limits” was intended to apply the *input* scope's global restriction; the explicit “do not trust imported scope” and “global import accepts” language supports the destination-scope interpretation used here. The two observed issues are independent of the shared macOS path-spelling test defect. No candidate source was modified.
