## Candidate-01

**Readiness: minor revisions.** The implementation reads input within bounds, checks destination paths before opening source files, collapses history, analyzes destination conflicts inside one transaction, and rolls back fully on database errors. It isolates project and global writes. Its contract defect is narrow but visible to users importing untrusted export scopes.

1. **Contract violation, high:** [`internal/memory/import.go:67`](/tmp/kgs-review/candidate-01/source/internal/memory/import.go:67) rejects a record whose *input* scope is `user:preferences` unless it is a preference without sources, even when the selected destination is a project. The task says imported scope is not trusted as destination identity and project import permits the record's valid project kind and sources. Reproduction: make an export-format row with positive ID, `scope:"user:preferences"`, `kind:"fact"`, valid text/evidence, and run `kiln memory import file.json` in a project. It exits 1 with `memory import has invalid global record`, although it should import into the project. The same check prevents `--on-conflict replace` from preserving local lineage for such input. **Reproduced by evaluator:** `project_scope_isolation` and `replace_lineage` fail with this diagnostic. The two failures share this cause. The expectation is supported by the explicit imported-scope rule; an original global database would not normally export such a row, so this matters primarily for adversarial or edited exports.
2. **Test portability, medium:** [`internal/memory/import_test.go:149`](/tmp/kgs-review/candidate-01/source/internal/memory/import_test.go:149) and [`internal/cli/memory_import_test.go:87`](/tmp/kgs-review/candidate-01/source/internal/cli/memory_import_test.go:87) compare canonical stored paths/scopes against the uncanonicalized `t.TempDir()` spelling. On macOS `/tmp` resolves to `/private/tmp`; the submitted unit and race runs fail on these assertions. Focused unit and race reruns with canonical `TMPDIR` pass. This is a test defect, not evidence of incorrect runtime rebinding.

Submitted tests cover CLI flags, size limits, scope, historical validation, source path escapes, stale sources, conflict policies, dry runs, cancellation, and injected rollback across memories/search/source tables. The rollback and cancellation design is credible. The suite misses the input-global-scope/project-destination distinction above, and its exact path assertions make the required checks environment dependent. Diagnostics are useful and do not echo memory content. Documentation describes limits, conflicts, rebinding, and output in [`docs/configuration.md:861`](/tmp/kgs-review/candidate-01/source/docs/configuration.md:861). Formatting, build, vet, staticcheck, targeted e2e, and 27 of 29 named hidden acceptance cases pass. The unchanged TUI test failure in the broad unit run was reproduced on baseline and is not attributed to this patch. Supplemental FIFO, count-boundary, dry-run-write, and trailing JSON probes pass.

## Candidate-02

**Readiness: minor revisions.** Normal CLI transfers and all 29 named hidden acceptance cases pass. History collapse, scope targeting, source rebinding, dry-run conflict analysis, and writes are coherent. The source type handling has a concrete local denial of service that needs a regression test and a guard before opening the path.

1. **Contract and security violation, high:** [`internal/memory/import.go:203`](/tmp/kgs-review/candidate-02/source/internal/memory/import.go:203) calls `sourceDigest` for a destination path without first checking its file type. Baseline [`internal/memory/sources.go:30`](/tmp/kgs-review/candidate-02/source/internal/memory/sources.go:30) opens the path before calling `Stat`. If the destination path is a FIFO, `kiln memory import` blocks at the open instead of rejecting the nonregular source. **Reproduced independently** with a temporary project containing `mkfifo pipe` and a valid export-format row pointing at relative source `pipe`: CLI timed out after 2 seconds. The evaluator's supplemental probe also terminated it after 3 seconds. No memory content is disclosed and no database write occurs before the block, but the required nonregular-file rejection and bounded local command behavior are violated. Candidate-01 avoids this with a resolved-target `Stat` before hashing.
2. **Test portability, medium:** [`internal/memory/import_test.go:197`](/tmp/kgs-review/candidate-02/source/internal/memory/import_test.go:197) requires stored canonical `Root` and `Path` strings to equal raw `t.TempDir()` strings. The initial unit and race runs fail under `/tmp` → `/private/tmp`; canonical-temp focused unit and race reruns pass. This is a submitted-test assertion defect. Its tests do not include FIFO/device sources, so the blocking path was missed.

The submitted tests cover malformed JSON and unknown fields, historical invalidity, expiry, source paths and staleness, scope isolation, conflicts, dry runs, cancellation, and injected transaction rollback. [`internal/memory/store.go:115`](/tmp/kgs-review/candidate-02/source/internal/memory/store.go:115) extracts Put validation for reuse; [`internal/memory/import.go:77`](/tmp/kgs-review/candidate-02/source/internal/memory/import.go:77) applies it to the destination scope, matching the contract. A single transaction contains conflict reads and writes, and errors return before success JSON. [`internal/cli/args.go:197`](/tmp/kgs-review/candidate-02/source/internal/cli/args.go:197) special cases import tokens in the general parser; this works for the specified syntax but couples the parser to subcommand ordering. I do not treat it as a contract defect. Documentation in [`docs/configuration.md:853`](/tmp/kgs-review/candidate-02/source/docs/configuration.md:853) is complete and clear. Formatting, build, vet, staticcheck, targeted e2e, and all hidden acceptance cases pass. The broad-unit TUI failure is unchanged baseline behavior. Supplemental count-boundary, dry-run-write, and trailing JSON probes pass; the FIFO probe fails.

## Comparison and uncertainty

Candidate-02 handles the imported-scope rule correctly and passes the named acceptance suite. Candidate-01 handles nonregular destination files more safely and passes the FIFO probe. Both have straightforward but mandatory fixes and nonportable new tests. Candidate-02's FIFO hang is the more serious security/resource issue; candidate-01's scope rejection is the more common semantic failure only if inputs contain an origin-global row invalid under original global rules. Neither patch has evidence of network/model calls, credential echoing, or transaction partial writes. File replacement races between validation and commit remain a potential limit of both implementations; I did not establish a reproducible violation, and the contract does not specify concurrent filesystem mutation semantics. A maintainer should confirm whether project import intentionally accepts origin-global rows inconsistent with the source database's global policy; I read the explicit instruction not to trust imported scope and the evaluator's scope cases as saying yes.
