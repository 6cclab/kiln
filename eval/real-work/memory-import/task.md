Users can export their memory but cannot transfer it safely to another project or machine. Add `kiln memory [global] import <file> [--dry-run] [--on-conflict error|skip|replace]`. Default conflict policy is error. Flags may follow the input filename; reject unknown flags, missing values, extra positional arguments, and invalid policy values. This is an explicit local management command and must not call a model.

Behavioral contract:
- Input is exactly one JSON array in the existing `kiln memory export` format. Reject malformed JSON, trailing JSON, unknown record/source fields, non-array/null input, files over 4 MiB, and more than 1000 records. Empty arrays are valid. Bound reading before allocation; do not read stdin when a filename is missing.
- An export contains history. Validate every record, then choose the largest input ID for each key as its current version. Input IDs must be positive and unique across the input; ties are invalid. Every record must satisfy existing Put field/kind limits; expires must be nonnegative. Do not trust imported scope, created, or supersedes values as destination identity or lineage.

An absolute source path is valid only when lexically contained in that original root; a relative source path is interpreted under that root. Never read original machine paths. Stale source-bearing records must be rejected, including historical records. Ordinary source-free project records remain valid.
- A conflict is any existing active destination key, even if expired or its source is stale. `error` rejects the whole batch; `skip` leaves existing records untouched; `replace` creates a new current record and preserves local correction history. For newly imported records assign destination IDs and current creation times; preserve expiry. Link supersedes to the previous destination record only.
